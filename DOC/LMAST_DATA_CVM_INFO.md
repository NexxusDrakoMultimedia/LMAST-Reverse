# Let's Make a Soccer Team (PS2) — DATA.CVM Decryption to DATA.ISO
Special thanks to **@tw09627** on the LMAST Discord, who first decrypted `DATA.CVM` with the help of
        ChatGPT and opened up the game's data for this project. This file is from his ChatGPT agent.

## Purpose

This document records the working process used to extract the encrypted `DATA.CVM` from the PAL PS2 version of **Let's Make a Soccer Team!** into a readable `DATA.ISO`.

The original `DATA.CVM` should always be kept untouched. Work from a copy.

---

## Recovered CVM / ROFS Key

The game does **not** appear to use a normal human-readable password for this archive.

The raw 8-byte ROFS key recovered from the running game is:

```text
5A FB 65 7D 4A 57 5F D5
```

This was confirmed dynamically in PCSX2:

- Key-generation call output buffer: `00A8652C`
- Actual decrypt routine: `001E72D8`
- `t0 = 00A8652C`
- `t1 = 00000008`
- Memory at `00A8652C` contained:

```text
5A FB 65 7D 4A 57 5F D5
```

This confirms that the same 8-byte key generated by the game is passed directly into the ROFS decryption routine.

## Patch cvm_tool to Use the Raw LMAST Key

Open:

```text
cvm_tool.cpp
```

Find the function:

```cpp
int cvm_to_iso(...)
```

Inside that function, locate the encrypted-CVM handling block.

Replace the password-based logic with:

```cpp
bool has_key = false;
unsigned char key[8];

if ( cvm.is_encrypted() )
{
    key[0] = 0x5A;
    key[1] = 0xFB;
    key[2] = 0x65;
    key[3] = 0x7D;
    key[4] = 0x4A;
    key[5] = 0x57;
    key[6] = 0x5F;
    key[7] = 0xD5;

    printf("Using LMAST raw key: ");
    for ( int i = 0; i < 8; i++ )
        printf("%02X", key[i]);
    printf("\n");

    has_key = true;
}
```

Immediately afterwards, the existing code should continue with something like:

```cpp
int isoStartSector = cvm.get_cvmh().isoStartSector;
int isoZoneSector  = cvm.get_zone().datalocISO.sector;

Iso9660Parser i9(
    inf,
    isoStartSector,
    isoZoneSector,
    has_key ? key : NULL,
    8,
    sectsize
);
```

The old code containing:

```cpp
CalcKeyFromString(password, key);
```

and:

```text
File is encrypted but no password was provided.
```

must **not** remain in the `cvm_to_iso(...)` extraction branch.

## Windows Build Fixes

The original repository is old and needs a couple of compatibility changes for current Visual Studio / CMake.

### 1. Replace `CMakeLists.txt`

Use:

```cmake
cmake_minimum_required(VERSION 3.10)

project(cvm_tool LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

add_executable(
    cvm_tool
    cvm_tool.cpp
    rofs_crypt.cpp
    iso_parser.cpp
    cvm_parser.cpp
)

if (NOT MSVC)
    target_compile_definitions(cvm_tool PRIVATE
        _FILE_OFFSET_BITS=64
        _fseeki64=fseek
        _ftelli64=ftell
        __int64=off_t
    )
endif()
```

This avoids old POSIX compatibility definitions breaking the modern Windows SDK.

### 2. Fix `_alloca` in `iso_parser.cpp`

Near the top of:

```text
iso_parser.cpp
```

change the old `_alloca` compatibility code so it becomes:

```cpp
#include "iso9660.h"
#include "rofs_crypt.h"
#include "iso_parser.h"
#include <malloc.h>
#include <memory.h>

#ifndef _MSC_VER
#ifndef _alloca
#define _alloca(x) __builtin_alloca(x)
#endif
#endif
```

On Microsoft Visual C++, `_alloca` is already provided by `<malloc.h>`.

## Troubleshooting

### Error: `File is encrypted but no password was provided`

This means the compiled executable still contains the original password-based extraction code.

Re-check `cvm_tool.cpp` and ensure the `cvm_to_iso(...)` function uses the raw key block above.

Then rebuild:

```text
cmake --build build
```

### CMake complains about missing `project()` or `cmake_minimum_required()`

Replace `CMakeLists.txt` with the version in this document.

### Hundreds of Windows SDK errors involving `off_t`, `time_t`, or `__time64_t`

This is caused by the old build file defining:

```text
__int64=off_t
```

for MSVC.

Use the replacement `CMakeLists.txt` above so those compatibility definitions are only used on non-MSVC builds.

### Error: `__builtin_alloca: identifier not found`

Apply the `iso_parser.cpp` `_MSC_VER` fix shown above.
